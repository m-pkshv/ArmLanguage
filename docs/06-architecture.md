# 6. Архитектура

## 6.1 Требования, которые определяют архитектуру

1. **Расширяемость.** Будут новые разделы (Чтение, Слова, Фразы, Грамматика), уровни сложности и
   типы заданий. Добавление не должно требовать переделки существующего.
2. **Статический хостинг.** GitHub Pages: только статические файлы, нет сервера и базы данных.
3. **Телефон и офлайн.** Быстрая загрузка, работа без интернета (PWA).
4. **Контент отдельно от кода.** Слова, картинки и уроки лежат в `content/*.json` и меняются без правки кода;
   Google-таблица для носителя — план ([4.9](04-content.md#49-как-ведётся-контент)).
5. **Надёжность прогресса.** Данные пользователя переживают обновления приложения (версии и миграции).

## 6.2 Технологии (решено)

| Что | Выбор | Почему |
|---|---|---|
| Язык | **TypeScript** | типы для контента и интерфейсов заданий — меньше ошибок при росте проекта |
| Сборка | **Vite** | быстрая, простая, стандарт де-факто |
| UI | **Svelte** | мало кода, маленький размер, встроенные анимации (переворот карточек, переходы) |
| Стили | CSS-переменные + обычный CSS в компонентах | без лишних зависимостей; цветовые темы — наборы переменных (`src/styles/palettes.css`) |
| PWA | vite-plugin-pwa | офлайн-кэш и установка на телефон |
| Тесты | Vitest (логика и контент) | сценарии на экране телефона проверяются вручную в браузере (375×812) |
| Публикация | GitHub Actions → GitHub Pages | автоматически при пуше в `main` |

Альтернативы (Preact/React, Vue, чистый JS) рассматривались; выбран Svelte.
Логика (`src/core`) пишется **без зависимости от UI-фреймворка**, поэтому фреймворк можно сменить.

## 6.3 Слои

```
┌──────────────────────────────────────────────────────────┐
│ UI: экраны, компоненты, отображение заданий (Svelte)     │
├──────────────────────────────────────────────────────────┤
│ Задания (плагины): генерация вопроса, проверка, вид      │
├──────────────────────────────────────────────────────────┤
│ Ядро (чистый TS, без UI):                                │
│  контент · прогресс/повторение · движок сессий ·          │
│  проверка ответов · утилиты армянского текста             │
├──────────────────────────────────────────────────────────┤
│ Платформа: хранилище · статистика посещений · PWA        │
└──────────────────────────────────────────────────────────┘
        ▲ данные: content/*.json, public/img/*
```

Правило зависимостей: верхний слой знает о нижнем, но не наоборот. Ядро не знает ни о Svelte,
ни о localStorage — всё внешнее передаётся через интерфейсы (хранилище, часы, генератор случайных чисел).
Поэтому логику легко тестировать.

## 6.5 Модель курса

```jsonc
// content/course.json
{
  "sections": [
    {
      "id": "alphabet", "title": "Алфавит", "status": "available",
      "lessons": [
        {
          "id": "alphabet-1",
          "title": "Первые буквы",
          "newItems": ["letter:ayb", "letter:men", "letter:nu", "letter:tyun", "letter:se"]
        }
      ]
    },
    { "id": "reading", "title": "Чтение", "status": "coming-soon", "lessons": [] },
    {
      "id": "first-words", "title": "Первые слова", "status": "available", "lessons": [],
      "themes": [                             // темы — в любом порядке, уроки внутри темы — по порядку
        { "id": "greetings", "title": "Знакомство и вежливость", "emoji": "👋", "status": "available",
          "lessons": [{ "id": "greetings-1", "title": "Приветствие", "newItems": ["word:barev", "phrase:barev-dzez"] }] }
      ]
    }
  ]
}
```
Раздел «Первые слова» — [10-first-words.md](10-first-words.md): элементы `word:…` и `phrase:…`, навыки `meaning`,
`produce`, `spell`; код — `src/core/words.ts`, `src/exercises/words/logic.ts` (задания W02–W09),
`src/session/wordPlan.ts` и `wordSelect.ts`, экраны `FirstWords.svelte`, `Theme.svelte`, `MyWords.svelte`.

- **Раздел** — набор уроков (или тем с уроками) + (при необходимости) свои типы элементов и заданий.
- Урок — только список новых элементов; какие задания давать, решает код по уровню знания
  (`src/session/select.ts`, `wordSelect.ts`), а не контент. Уроки открываются по порядку (`src/core/course.ts`).
- **Сложность** растёт вместе с коробкой интервального повторения и задаётся внутри типа задания (параметры генерации).
- Новый раздел = новый файл контента + запись в `course.json` + при необходимости новые типы заданий.

## 6.6 Элементы знания и навыки

```ts
type ItemKind = "letter" | "word" | "phrase";          // расширяется
type ItemId = `${ItemKind}:${string}`;                  // "letter:tho", "word:dzuk"
type Skill = "recognize" | "recall" | "read" | "case" | "handwriting" | "discriminate" | "listen" | "write"
  | "meaning" | "produce" | "spell";                     // слова и фразы: понимание, вспоминание, по буквам
// описание навыков и какие из них «основные» — в 03-exercises.md#навыки
```

Прогресс хранится для пары **(элемент, навык)**: `letter:tho#recall`. Разделы используют общий механизм:
в «Первых словах» элементы — `word:…` и `phrase:…`, навыки — `meaning`, `produce`, `spell`
([10-first-words.md](10-first-words.md)).

## 6.7 Типы заданий как плагины

Каждый тип задания — логика (чистые функции) и вид (компонент), зарегистрированные в `src/exercises/logic.ts`
и `src/exercises/registry.ts`.

```ts
interface ExerciseType<Q, A> {
  id: string;                          // "ru-word-insert"
  title: string;                       // «Вставь армянскую букву»
  itemKinds: ItemKind[];               // для каких элементов подходит
  skills: Skill[];                     // какие навыки тренирует
  difficulty: [min: number, max: number];

  /** Можно ли построить задание для элемента с учётом того, что уже изучено. */
  isApplicable(item: Item, ctx: GenContext): boolean;

  /** Построить вопрос. ctx даёт контент, изученные элементы, rng, уровень сложности. */
  generate(item: Item, ctx: GenContext): Q;

  /** Проверить ответ. Возвращает вердикт и влияние на прогресс по каждому элементу. */
  check(question: Q, answer: A, ctx: CheckContext): CheckResult;

  /** Компонент отображения: получает вопрос и сообщает ответ. */
  view: Component<{ question: Q; onAnswer: (a: A) => void }>;
}

interface CheckResult {
  verdict: "correct" | "partial" | "wrong";
  effects: { item: ItemId; skill: Skill; verdict: Verdict }[];   // одно задание → несколько букв
  confusions?: { expected: ItemId; given: ItemId }[];            // для статистики путаниц
  explanation: Explanation;                                       // что показать пользователю
}
```

**Как добавить новый тип задания:**
1. Добавить id в `ExerciseId` (`src/core/session/types.ts`).
2. Написать логику (`generate`, `check`, `isApplicable`) и зарегистрировать в `src/exercises/logic.ts`.
3. Написать вид в `src/exercises/views/` и зарегистрировать в `src/exercises/registry.ts`.
4. Добавить тип в таблицу выбора (`src/session/select.ts`) и/или в список «Своей тренировки».
5. Тесты: `tests/exercises.test.ts` автоматически проверит новый тип на всех буквах.

Остальной код (движок сессий, прогресс, экраны) не меняется.

## 6.8 Движок сессии

1. **Планировщик** собирает очередь элементов: новые элементы урока + элементы, у которых подошёл срок
   повторения (`due ≤ сейчас`), + немного «трудных».
2. Для каждого элемента **выбирает тип задания**: из разрешённых уроком, применимых к элементу,
   по сложности подходящих к уровню самого слабого навыка; без повторов одного типа более 2 раз подряд.
3. После ответа применяет `effects` к прогрессу, при ошибке возвращает элемент в конец сессии.
4. В конце — итог и сохранение.

Движок детерминирован при заданном `rng` и `clock` → воспроизводимые тесты.

Отдельно от прогресса, в `localStorage["hy:seen-version"]`, — какая версия «Что нового» уже показана
(удобство, не часть прогресса).

### Где хранится прогресс (без сервера)

| Этап | Способ | Стоимость | Что даёт |
|---|---|---|---|
| V1 | **Хранилище браузера** (localStorage) | бесплатно, сервер не нужен | прогресс сохраняется между сессиями на том же устройстве и в том же браузере |
| V1 | **Защита от удаления:** запрос `navigator.storage.persist()` + совет установить приложение на главный экран (PWA) | бесплатно | браузер не удалит данные при нехватке места. Safari на iPhone стирает данные сайта после 7 дней пользования браузером без захода на этот сайт, но не трогает установленные на главный экран приложения. Chrome, Яндекс Браузер и другие браузеры на iPhone работают на том же движке WebKit, но формально правило касается только Safari. Гарантий нет, поэтому надёжные способы — установка на экран, резервная копия, позже облако |
| V1 | **Экспорт/импорт файла** + подсказка на главном экране раз в неделю «сохраните копию» | бесплатно | резервная копия, перенос на другое устройство вручную |
| Позже | **Облачная синхронизация**: вход через Google, прогресс хранится в Firebase (бесплатный тариф Spark) или Supabase (бесплатный тариф) | бесплатно при небольшом числе пользователей (тысячи в день) | один прогресс на всех устройствах, данные не теряются при очистке браузера |

Сам сайт остаётся на GitHub Pages; облачная база подключается как внешний сервис, свой сервер писать не нужно.
Приложение продолжает работать без входа и без интернета, а синхронизация выполняется, когда сеть появляется.

- Хранилище за интерфейсом `ProgressStore` (`load`, `save`, `export`, `import`). Сейчас — localStorage,
  при сбое — работа в памяти с предупреждением. Позже — синхронизация с облаком без изменения ядра.
- **Версия схемы + миграции:** при изменении формата пишется функция миграции `v1 → v2`,
  старые данные пользователей не теряются.
- Интервальное повторение — отдельный модуль с чистыми функциями (`review(state, verdict, now) → state`);
  алгоритм можно заменить (Leitner → SM-2/FSRS), не трогая остальное.

## 6.10 Маршрутизация

Hash-маршруты (`#/alphabet/tho`): GitHub Pages не умеет отдавать `index.html` на произвольные пути,
а hash-маршруты работают без настройки сервера.

## 6.11 Сборка, проверки, публикация

Контент правится в `content/*.json` и сохраняется в репозиторий как обычное изменение (скрипт
`content:pull` из Google-таблицы — план, [4.9](04-content.md#49-как-ведётся-контент)).

GitHub Actions (`.github/workflows/deploy.yml`) при каждом пуше в `main`:
1. установка зависимостей (`npm ci`);
2. `check` — проверка типов Svelte/TypeScript;
3. `test` — все тесты, включая проверку контента (`tests/content.test.ts`);
4. `build` — сборка в `dist/` (с `BASE_PATH=/ArmLanguage/`);
5. сборка сайта (приложение в корне, прототип `legacy/` — в `/old/`) и публикация на GitHub Pages.

## 6.12 Производительность

- Первая загрузка ≤ 300 КБ (gzip) без картинок; картинки подгружаются лениво.
- Шрифты (Fontsource, в офлайн-кэше): Inter, Noto Sans Armenian, Lora (заголовки темы «Дилиджан» —
  только кириллица и латиница), `font-display: swap`.
- Контент сейчас встроен в код приложения целиком (он небольшой); загрузку по разделам стоит сделать,
  когда разделов станет много.

## 6.13 Интернационализация

Все тексты интерфейса — в `src/i18n/ru.json`. Объяснения в контенте хранятся с ключом языка
(`"ru": "…"`). Это позволит в будущем сделать версию для англоязычных, не меняя код.

## 6.14 Судьба прототипа v0.1

Прототип перенесён в папку `legacy/`. Сайт устроен так:
- `https://m-pkshv.github.io/ArmLanguage/` — новое приложение (переменная сборки `BASE_PATH`);
- `https://m-pkshv.github.io/ArmLanguage/old/` — прототип, пока новое приложение не заменит его функции.

Новое приложение давно заменило прототип; его можно убрать в любой момент (удалить `legacy/` и строки
копирования в `deploy.yml`) — по решению владельца.
